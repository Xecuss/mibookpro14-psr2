# 调查过程简记

| 阶段 | 发现与转向 |
|---|---|
| 早期Linux/上游记录 | 比较SCL、guardband、idle_frames和VRR未知位等差别，相关尝试未解决本机现象；不能因此认定所有时序影响均已排除。 |
| 区域门槛实验 | 通过0005将超过N行的区域改为CFF；35仍有底部花屏，3下不花且能深睡。说明更新处理方向值得调查，未证明大区域是根因。 |
| 本机Windows参考 | GUI只读采集到正常104行底部partial，补抓plane3也吻合；同时存在全屏partial，推翻“Windows从不用全屏partial”的假设。 |
| 2026-10-15：0006 | 在plane计算前使用104纵向网格，保留ET光标覆盖；底部局部更新、不花、深睡、恢复验收通过。Linux实际非DSC。 |
| 2026-10-15：静置功耗 | Linux104与PSR1接近；Windows参考受亮度/HDR和计量更新限制，不能作精确跨系统比较。 |
| 2026-10-16：其他网格 | 52/208被报花、无日志；26预计无效回退4。80底部/输入/鼠标通过且有partial/深睡日志，证明104不是唯一有效值。 |
| 2026-10-16：视频功耗 | 每轮重启的PSR1/104/80对照：两轮PSR2均较低，但80/104耗能几乎相同，未确定网格功耗赢家。 |
| 当前 | 用户选择104作为日常候选，整理公开仓库；根因未闭环，暂不向上游提报、不扩展quirk。 |

Windows旧RWE命令行曾触发蓝屏，离线分析定位到驱动卸载清理路径；后续持久GUI读成功不代表卸载问题修复。本仓库只提供已采结果节选，不提供RWE驱动/可执行程序、自动读取或退出入口，也不要求更改Windows安全设置或再做MMIO采集。

完整实验和交接过程留在原调查工作区。公开[data](../data/)保留结论依据；补丁提交说明已按当前证据修订，diff代码保持测试版本不变。
